# Architecture decision records

Architecture decision records (ADRs) capture durable choices whose rationale would otherwise be lost across issues and pull requests. Use an ADR for material changes to architecture, public data contracts, provider/cost policy, security boundaries, publishing guarantees, or governance.

## Index

No accepted ADRs have been backfilled. New decisions start from [the template](template.md) and use `NNNN-concise-title.md`. Status is one of Proposed, Accepted, Superseded, or Rejected. A superseding ADR links both directions.

An ADR explains why a choice was made; an implementation design explains how a scoped change will be delivered.
